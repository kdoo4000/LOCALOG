# LOCALOG UI 점검 · 2026-10-05

## 기준

- 기존 파란색, 따뜻한 배경색, Pretendard 유지.
- 페이지 좌우 여백 24, 섹션 간격 24~28, 입력칸 간격 16.
- 주 행동과 보조 행동 버튼 높이 56. 대화상자는 양쪽 버튼 높이 52와 동일 너비.
- 프로필·팔로워·동행자에 같은 아바타, 이름, `@아이디` 배치 사용.
- 메뉴 밑의 반복 안내 문구 추가하지 않음. 선택한 조건·금액·역할 같은 실제 정보는 유지.

참고: [Instagram 공식 그룹 프로필 화면](https://about.fb.com/news/2022/12/sharing-features-on-instagram-notes-group-profiles-and-more/), [Instagram 공식 그룹 초대 화면](https://about.fb.com/news/2025/02/new-instagram-dm-features-stay-connected/). 화면 배치 참고 자료이며 기능을 추가하거나 현재 정책을 그대로 따르지는 않았다.

적용 스킬: `redesign-existing-projects`, `ui-ux-pro-max`. 추천 결과에서 현재 앱과 맞는 단일 열, 터치 크기, 폼·키보드·여백 기준을 적용했다.

## 화면 파일 전체 조사

24개 `*_screen.dart`와 `photo_location_page.dart`를 대상으로 조사했다. 화면 파일 안에 포함된 회원가입, 검색 결과, 팔로워 목록, 지출 입력 상태도 점검했다.

| 화면 | 조치 |
|---|---|
| 시작·온보딩 | 기존 브랜드 구성 유지, 공통 테마 적용 |
| 로그인·회원가입·약관 | 폼 테두리·라벨 통일, 약관 대화상자 여백과 버튼 정리 |
| 메인 메뉴·홈 | 메뉴 구성 유지, 큰 글씨에서 인기 장소 카드 높이 부족 수정 |
| 검색·상세 검색·검색 결과 | 불필요한 추천 안내 제거, 큰 글씨에서 고정 비율 그리드 대신 목록 사용 |
| 지역 선택 | 공통 입력창·버튼 크기 적용 |
| 장소 검색 지도 | 지도와 결과 영역을 남은 높이에 맞춰 배분, 가로 화면 넘침 수정 |
| 장소 상세·로그 상세 | 기존 콘텐츠 구성 유지, 공통 버튼 테마 적용 |
| 로그 가져오기·장소 편집 | 입력 테두리 덮어쓰기 제거, 공통 둥근 모서리와 여백 적용 |
| 사진 업로드·편집·미리보기 | 업로드 카드와 단계 표시 사이 24 여백 추가, 중복 안내 박스 제거, 취소 대화상자 통일 |
| 내 프로필 | 큰 배너를 밝은 프로필 카드로 변경, 아바타·아이디 중심 배치 |
| 공개 프로필·프로필 수정 | 팔로우 버튼과 숫자 영역 분리, 로그 카드·빈 상태 정리, 입력칸 간격·버튼 크기 통일 |
| 사람 찾기·팔로워·팔로잉 | 아바타 목록, 동일한 좌우 여백, 검색 진행·결과 없음 상태 적용 |
| 내 여행·받은 초대 | 초대 카드 사이 간격 추가, 참여·거절 버튼 동일 크기로 분리 |
| 여행 생성·수정·상세 | 입력 테두리·본문 여백 통일, 동행자 아바타 목록 적용 |
| 계획 루트 편집 | 전체 입력 영역을 스크롤할 수 있게 변경, 가로 화면과 키보드에서 잘림 수정 |
| 계획 로그 발행 | 공통 입력 테두리 적용, 사진 추가 버튼의 무한 너비 문제 해결 |
| 동행자 초대 | 코드 공유·현재 동행자·사람 검색 구역 분리, 아바타 목록, 부가 동작은 메뉴로 이동 |
| 코드 공유·코드 입력 | 코드 카드·버튼 간격 정리, 입력 중 미리보기와 코드가 어긋나지 않도록 조회 중 입력 잠금 |
| 여행 정산·지출 등록 | 지출 카드 간격, 금액·행동 분리, 입력칸 간격, 아바타·분담 목록 정리 |
| 영수증 정산 | 총액 수정·확인 대화상자 통일, 공통 버튼 높이 적용 |

공통 원인도 수정했다. `Size.fromHeight`의 무한 너비가 일반 버튼 테마에 지정되어 일부 `Row`에서 렌더링 오류를 만들었으므로 공통 최소 너비를 유한 값으로 바꾸고, 화면 전체 너비가 필요한 위치에서만 너비를 지정했다.

## 검증

최종 결과: 기본 전체 테스트 137개 통과. 기본 실행에서 제외되는 로그인 화면 전용 검사 3개는 가짜 서버 설정으로 별도 실행하여 모두 통과했다. `flutter analyze --no-pub`도 지적 사항이 없었다.

- `test/ui_layout_audit_test.dart`: 업로드 카드 간격, 입력칸 간격, 대화상자 버튼 크기, 작은 화면의 긴 프로필 이름.
- `test/ui_screen_audit_test.dart`: 주요 화면을 390×844, 320×720 / 글씨 1.6배, 844×390 / 글씨 1.4배, 1200×900에서 렌더링하고 아래쪽까지 스크롤. 회원가입·검색 결과·키보드 상태 포함.
- `test/social_ui_audit_test.dart`: 로그인 사용자 프로필·초대·코드 생성·정산·지출 입력을 로컬 HTTP 응답으로 렌더링. 실제 서버 데이터에 쓰지 않음.
- 기존 ID 저장, 중복 ID 오류 유지, 팔로우, 여행 계획, 영수증 관련 전체 테스트도 실행.

재실행 명령:

```powershell
flutter test --no-pub
flutter test --no-pub test/social_ui_audit_test.dart --dart-define=SUPABASE_URL=https://example.test --dart-define=SUPABASE_PUBLISHABLE_KEY=ui-test-public-key
flutter analyze --no-pub
```

미리보기는 두 화면 검사 명령에 `--dart-define=WRITE_UI_PREVIEWS=true`를 추가하면 `build/ui-audit/`에 저장된다. 해당 이미지는 실제 Flutter 위젯을 테스트 데이터로 렌더링한 것이며 실기기 캡처는 아니다. 지도 서비스의 실기기 표시와 사진 선택 네이티브 창은 이번 위젯 점검의 범위 밖이다.

APK는 빌드하지 않았다.
