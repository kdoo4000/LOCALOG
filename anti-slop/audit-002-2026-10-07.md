# LOCALOG UI 디자인 검증 · 2026-10-07

antislop AFTER 모드. 제품 코드를 변경하지 않고 현재 렌더링과 원인을 확인했다.

후속 상태: 사용자 요청으로 5개 항목을 수정했다. [수정 결과](fixes-002-2026-10-07.md)를 참고한다. 아래 화면 링크는 재캡처한 수정 후 화면을 가리킨다.

## 결론

기본 모바일 화면의 파란색·따뜻한 배경·Pretendard·버튼 체계는 일관된다. 그러나 **상세 제목 가림, 상세 헤더 대비, 확대 시 정산 요약 가독성**은 해결이 필요하다. 레이아웃 예외가 없다는 결과만으로 디자인 통과를 판단할 수 없다.

## 범위와 방법

- 기존 화면 캡처에서 로그인·회원가입·홈·탐색·프로필·초대·여행·정산 등 31개 화면/상태를 검토했다.
- 기존 화면 검증을 임시 복제해 390×844/100%, 320×720/200%, 844×390/200%, 1200×900/100%에서 다시 실행하고 확대·태블릿 캡처를 추가했다.
- 화면 렌더링/스크롤 4개 검사와 프로필 수정 키보드 검사 1개, **총 5개 검사 통과**. 임시 검사 파일은 제거했다.
- 주요 확대 화면은 직접 이미지로 검토하고 코드에서 고정 높이, 줄 수 제한, 색상, 공통 위젯 사용처를 확인했다.
- 위젯 렌더링 기준이다. 실제 기기 상태 표시줄·키보드·지도·사진 선택기, 운영 데이터와 브라우저 렌더링은 이번 검증에 포함하지 않았다. 비동기 이미지/폰트가 준비되지 않은 캡처의 회색 면·글자 블록은 제품 결함으로 집계하지 않았다.

## 발견 사항

### 1. HIGH · 로그 상세 제목이 본문에 가려짐

- 규칙: R-03, R-34, C-4.
- 조건: 320×720/200%, 844×390/200%에서 재현. 가로 화면에서는 제목이 거의 보이지 않는다.
- 증거: [작은 화면](../build/ui-audit/compact-route-detail.png), [가로 화면](../build/ui-audit/landscape-route-detail.png).
- 원인: `route_detail_screen.dart`의 별도 배경 헤더와 본문 `Stack`, 화면 높이 기반 `coverHeight`, 초기 `coverHeight * 0.5` 스크롤. 늘어난 제목·태그 높이를 본문 시작 위치가 반영하지 않는다.
- 권장: 제목·작성자·태그가 본문에 가려지지 않게 실제 콘텐츠 높이에 맞춰 흐름을 구성한다. 초기 자동 스크롤도 제목 가시성을 보장해야 한다.
- 확인 조건: 두 확대 화면에서 제목·작성자가 읽히고 본문이 겹치지 않는다.

### 2. HIGH · 장소 상세의 상단 제목/뒤로 가기 대비 부족

- 규칙: R-03.
- 조건: 펼쳐진 장소 상세 헤더. 기본 글씨에서도 발생한다.
- 증거: [장소 상세](../build/ui-audit/place-detail.png).
- 원인: `place_detail_screen.dart:77`의 `SliverAppBar`가 파란색/사진 위에서도 `foregroundColor: AppColors.ink`를 사용한다. 하단 장소명은 흰색이라 상단 제목과도 일관되지 않는다.
- 대비: 원색 `#2457F5`와 `#101828`의 대비는 **3.17:1**. 일반 크기 제목 기준 4.5:1에 미달하며, 사진에서는 더 불안정하다.
- 권장: 펼쳐진 헤더에서 흰색 전경과 안정적인 배경 처리를 적용하고, 접힌 밝은 앱바에서는 진한 전경을 사용한다. 사진·파란색 대체 배경 모두 확인한다.
- 확인 조건: 펼침·접힘 상태의 제목과 뒤로 가기 버튼이 모두 명확하다.

### 3. MEDIUM · 확대 시 정산 요약이 한 글자씩 줄바꿈됨

- 규칙: R-03, R-34, C-4.
- 조건: 영수증 정산, 320×720/200%.
- 증거: [정산 요약](../build/ui-audit/compact-settlement.png).
- 원인: `premium_ui.dart:256`의 `AppMetricStrip`이 항상 3개 `Expanded` 열로 배치한다. 좁은 카드 안에서 `확인 전`이 세로로 분해되고 요약 높이가 과도하게 커진다.
- 영향 범위: 영수증 정산 외에 내 여행·여행 지출·사진 업로드 결과도 같은 위젯을 사용한다. 이 화면들의 실제 값도 함께 확인해야 한다.
- 권장: 좁은 유효 너비/큰 글씨에서는 항목을 행으로 재배치한다. 금액과 단위를 읽기 쉬운 묶음으로 유지한다.
- 확인 조건: 320/200%에서 라벨·금액·단위가 한 글자씩 끊기지 않는다. 긴 금액도 확인한다.

### 4. MEDIUM · 홈의 핵심 여행 제목이 확대 시 생략됨

- 규칙: R-34, C-4.
- 조건: 320×720/200%, `함께 떠나는 부산 여행`.
- 증거: [홈 메인 화면](../build/ui-audit/compact-main-shell.png).
- 원인: `home_screen.dart:452`의 제목을 2줄/ellipsis로 고정해 `함께 떠나는 부산 …`까지만 보인다.
- 권장: 홈의 대표 여행 제목에는 확대 시 더 많은 줄을 허용한다. 목록의 긴 제목 생략과 구분해서 적용한다.
- 확인 조건: 위 제목이 200%에서도 완전히 읽히며 CTA가 계속 스크롤로 접근 가능하다.

### 5. LOW · 태블릿의 사진 비율과 버튼 너비가 콘텐츠에 비해 과도함

- 규칙: R-05, R-34, C-4. 접근성 실패가 아니라 디자인 개선 항목이다.
- 조건: 1200×900/100%.
- 증거: [태블릿 홈](../build/ui-audit/tablet-main-shell.png), [여행 생성](../build/ui-audit/tablet-trip-create.png).
- 원인: 로그 카드 사진은 너비만 늘어나고 높이는 184로 유지되어 매우 긴 가로 띠가 된다. 여행 생성의 중앙 폼과 하단 화면 전체 너비 버튼이 서로 다른 축을 쓴다.
- 권장: 넓은 화면에서 사진 비율을 유지하도록 카드 너비/배치를 조정하고, 폼 하단 버튼을 폼의 읽기 너비에 맞춘다. 새로운 레이아웃 체계보다 기존 너비 토큰을 우선 사용한다.
- 확인 조건: 사진이 지나치게 잘리지 않고 입력 영역과 주 버튼의 정렬이 연결된다.

## 양호한 부분

- 기본 모바일 화면에서 브랜드 색상, 본문 폰트, 폼 테두리, 둥근 모서리, 주 행동 버튼의 일관성이 유지된다.
- 320/200%에서도 하단 5개 메뉴의 아이콘·이름을 읽을 수 있다.
- 프로필 수정은 버튼 두 개의 크기·배치가 균형적이고 키보드가 올라온 뒤 저장 버튼에 접근할 수 있다.
- 기본 모바일의 여행 생성·장소 추가·로그 편집은 입력 순서와 주 행동이 분명하다.
- 최근 수정에서 제거한 장식/허위 지표가 다시 생기지 않았다. 기존 예시 모드 고지는 개별 화면 캡처 바깥의 앱 공통 영역에 있으므로 캡처에서 안 보이는 사실만으로 누락 판정하지 않았다.

## 수정 우선순위

1 → 로그 상세 제목 가림과 장소 헤더 대비를 먼저 수정한다.

2 → 공통 정산 요약의 재배치와 홈 대표 제목 줄 수를 수정한다.

3 → 태블릿 사진·폼 버튼 정렬을 정돈한다.

이번 검증은 제품 코드 수정 없이 완료했다. 새 디자인 체계·기능·라이브러리는 필요하지 않다.
